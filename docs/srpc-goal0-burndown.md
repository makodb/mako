## How to use this

Work top-down through **Convertible now** — those need no transpiler
work, only the idiom named in each row. Tick items off as they land.
After each batch: regenerate, `build2.sh all` into a log and grep THE
log, then a full gate (build 0 errors + ctest failing-set == only
`rpcbench`) **before** pushing. A clean build is NOT sufficient — run the
integration suites too; a `move ||` capture bug once passed compilation
and was caught only by two runtime tests.

Checkbox legend: `[ ]` open · `[x]` landed · `[~]` blocked on something
environmental (e.g. a platform we cannot build here), see the row note.

## Idioms learned while landing these

Add to this list as the campaign continues — each one cost a build cycle
to discover.

- **`&mut local` lowers to a POINTER; `&local` on a pointer-like local
  (Arc/Rc) collapses to the handle.** When a C++ callee takes `T&`, go
  through a named binding: `let r: &mut T = &mut x; callee(r);`. This
  bites `recycle(&mut fiber)`, `write_fn(&mut ar)`, and the
  `Waker`/`Context` poll call.
- **A DSL `&mut` PARAMETER, by contrast, passes through as a C++
  reference.** So kernel signatures differ: archives (params) take `&`,
  locals take `*`.
- **`move ||` closures MOVE their captures.** Anything used after the
  closure needs an explicit `.clone()` first — this silently produced a
  moved-from (null) `Arc` return in `request_with_options` that only two
  integration tests caught.
- **`Default::default()` infers only in typed-let position**, never as a
  bare argument. Bind it first.
- **`T::new(...)` looks for a static `new_` factory**, so a hand-written
  C++ type with a real constructor needs a one-line construction kernel.
- **Spelling `rusty::Function<...>` inline as a DSL param type is a
  parse error** — use the file's existing type alias.
- **Two impl blocks in one `#if RUSTYCPP_RUST` merge into one struct**,
  which is how to get a const/non-const overload pair.
- **`#[cpp_ctor]` zero-arg emits a real default constructor** — the only
  way to keep `T x;` call sites valid, since the DSL has no default
  field initializers.
- **A fn returning a CLASS type mis-qualifies unqualified free-fn calls
  against that return type** (`rusty::Rc<Fiber>::Log_debug`). Qualify
  them `rrr::Log_debug(...)`. Odd nuance: sibling calls in the same body
  were *not* mis-qualified — only the bare call inside an `unsafe {}`
  statement block. Still an open transpiler defect.
- **New container methods auto-extend the `GEN-DISPATCH` block.** The
  first `.pop()` in a file makes the transpiler add
  `RUSTY_METHOD_DISPATCH(pop)`; a missing one is a hard compile error, so
  confirm the block grew after regenerating.
- **`assert!(cond, "msg")` emits `if (!(cond)) throw ...`** — the
  condition is INVERTED relative to the `throw` it replaces.
- **Reaching a `BoxEvent` behind `Option<Arc<...>>` needs an explicit
  deref**: `let ev = self.state_.as_ref().unwrap(); (*ev).get()`. The
  naive chained `.get()` binds `Arc::get` and returns a pointer.
- **Read clang's instantiation notes bottom-up and do not assume the
  adjacent chain is causal.** A long `Vec<T>::clone` note series sitting
  directly above an error can belong to an entirely different,
  successful instantiation. Find the `error:` line's OWN "requested
  here" chain before theorising.
- **`reactor_create_sp_event<Ev>()` is the GENERIC registration
  template**, and forwards its pack to `Arc<Ev>::make(...)`. DSL-emitted
  event structs have only a fieldwise ctor, so calling it with no
  arguments is a hard error. Use the typed factory
  (`create_sp_int_event(target)` and friends).
- **A foreign C++ enum can still be mis-lowered as a DSL variant
  ACCESSOR** (`FrameDecodeStatus::Complete()` — a call to something that
  is not a function). Force path lowering by comparing through casts:
  `(s as i32) == (Foo::Bar as i32)`.
- **DSL enum accessors emit into the enclosing namespace.** A body in a
  DIFFERENT namespace (e.g. `janus` using an `rrr` enum) must spell the
  variant qualified — `rrr::EventStatus::DONE` — or the emitted
  `EventStatus_DONE()` is undeclared there.
- **Calls between DSL blocks lower differently than calls within one.**
  A `&mut local` argument becomes a POINTER when the callee lives in a
  *different* `#if RUSTYCPP_RUST` block, but lowers correctly inside the
  same block — so merge caller and callee into one block when passing
  `&mut`.
- **Pair-yielding map iteration (`for (auto [k,v] : map)`) has no DSL
  spelling.** The cheap workaround is a 3-4 line kernel that snapshots
  the KEY SET into a `Vec`, after which the loop body is fully DSL and
  re-`get()`s per key (which is also more robust against entries erased
  mid-sweep).
- **A `std::vector<T>` parameter survives the DSL.** `fn f(out: &mut
  std::vector<u8>)` lowers verbatim to `std::vector<uint8_t>&` — a DSL
  body does NOT force callers onto `rusty::Vec`.
- **`format!` wraps its arguments in `rusty::to_string`; `std::format`
  called directly from a DSL body does not.** When a log/format site
  fails with "`to_string` must be declared", the fix is usually to spell
  `std::format(...)` in the DSL rather than to hunt for the right
  include — it is also exactly what the C++ path already did.
- **A fn-body `static NAME: T = init();` lowers to a real C++ magic
  static** — lazy, thread-safe, init-once semantics preserved.
  `#[thread_local] static mut` gives `static thread_local T`. So
  "function-local static" was never a DSL blocker.
  (Both of the hazards previously noted here — `return NAME;` moving out
  of the static, and a dynamic initializer being hoisted above an earlier
  guard — are FIXED in the transpiler as of verify-stack 7cc3a6da, with a
  regression test each. Constant-initialized statics still hoist, which is
  what lets a hoisted local struct's Drop impl reference them.)
- **`std::string()` works** as a plain call on a foreign type's path, in
  return/tail/let/argument position — there is no "cannot default-construct
  a foreign type" limit.
- **A foreign-enum variant mis-lowered as a nullary call is dodged by an
  UNTYPED `let`**: `let refused = rusty::io::Error::Kind::ConnectionRefused;`
  then compare against the binding. Dropping the expected type routes the
  path through ordinary path emission.
- **A DSL generic emits a real `template<typename T>`** — no type
  erasure, no monomorphization cost. "Hot-path template dispatch" is
  therefore never a reason to keep something a kernel.
- **A DSL struct cannot be a base class with a real constructor**, but a
  4-line subclass shim on the *consumer's* side bridges it
  (`QuorumEventBase`, `janus::Command`). Prefer that to pinning
  ergonomic C++ inside `src/rrr`.
- **Deleting a block by matching its first/last line: do NOT `.strip()`
  the terminator.** An indented inner `}` compares equal to the closing
  `}` and you will delete half a function, orphaning a brace. Anchor on
  the exact line text, and never substring-match a GEN id (`server.1`
  also matches `server.14`).
