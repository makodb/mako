# Private resolved-identity cache

Production sources remain unchanged. Baseline is `base/crates`; the sole cache arm is `cache/crates`. Both carry the same private benchmark workload module and use Rust 1.95.0, non-LTO, znver1, frame pointers, and debug info level 1 through `build.sh`. Entries have64-byte alignment so each64-byte entry occupies one cacheline on the target machine.

The cache holds 512 direct-mapped entries, each 64 bytes, for exactly 32 KiB of Vec element capacity per worker/database attachment. This excludes allocator bookkeeping, rounding, and RSS effects. It is allocated once using `try_reserve_exact`; failure or unexpected excess capacity disables it. Entry metadata adds the Vec and RefCell control words to WorkerSlot, but no transaction-owned allocation. Keys longer than 32 bytes bypass before hashing or borrowing the cache. There is no eviction destructor beyond replacing a Copy identity token.

The cache owns copied key bytes and opaque `ResolvedRecord` tokens only. It holds no row version, presence, value, raw record pointer, native worker borrow, or transaction borrow. A hit requires exact key length/bytes plus the table's runtime/object ownership check. A hash collision merely replaces a bucket. Per-worker scope follows the existing process-lifetime attachment contract. The facade cap is460 workers, so entry capacity can reach14.375 MiB per database. The benchmark's32-worker cap uses1 MiB. Historical database epochs are not globally bounded under the existing retention model.

`Table::put_resolving_with_previous_presence` uses the same `with_key_record_lookup` callback as the original PUT. It stages an owned Value and returns presence plus the identity already resolved by that callback. It retains the original missing-record publication and `account_own_publication` handling. A token is remembered only after the complete operation returns success. Creating a stable tombstone can still remain after transaction abort, as in the original API, and its identity remains valid after delete/reinsert.

Hits call the existing safe `put_resolved_with_previous_presence` API, including runtime/object validation, current-row observation, repeated-write state, and ordinary OCC validation. Misses call the new resolving API once. Disabled caches and long keys call the original PUT. No borrowed staging, OCC shortcuts, speculative presence, or new unsafe code is introduced. Cache RefCell borrows end before STO access or callbacks. The cache remains owned by WorkerSlot across fused facade forget and quarantine, so it introduces no terminal transfer or drop obligation.

The private benchmark adds key cardinality, length, distribution, table count, and seed. Both arms share identical source. Keys use a reused1024-byte stack buffer, and record terminals use a reused2048-byte stack buffer. The128-byte value generation is unchanged. Scheduling adds shared runtime modulo/hash work; it allocates nothing per operation. Verification replays the exact schedule outside timing and checks the last expected value for every touched table/key identity. All result fields include defaults. Stream rejects explicit cardinality. Domain/product/queue limits are checked before database creation.

Required trials include hot256/1024, cycle16K, stream, uniform16K, skew16K, key widths32/33/64, and mixed two-table hot256. W1 covers all cases; W4 and W32 hot subsets follow only if initial results justify them. Long-key and high-cardinality misses must be included before judging benefit. No remote measurement may overlap the performance agent's lock.

The third arm is `cache-prefetch/crates`. Its only changes from the cache arm are the exact previously tested prefetch helper, Clock address accessor, restricted-write hook call, and cold attachment initialization. The helper file is byte-identical to the earlier private experiment. Cache+prefetch has the same workload source, flags, and native archives as the other two arms. See `RESULTS.md` for executed checks and immutable identities. This prototype is not a production promotion or a release qualification claim.
