# sRPC scaffolding conversion plan

## Objective

Make `crates/srpc` the authored source for the C++20 modules currently kept in
`src/rrr`.  Mako continues to compile C++ generated by rusty-cpp, but module
preambles, imports, namespace walls, declarations, and compatibility shims are
generated from one consumer manifest rather than maintained by hand.

The post-pilot baseline is **1,202 census scaffold lines** plus **35 census
logic lines**, all 35 of which belong to the C-compatible fiber ABI header.
The target of this campaign is to retire roughly 1,050--1,100 lines of named
C++ module scaffolding.  `reactor/srpc_fiber.h` is a separate C/assembly ABI
artifact, and `std_compat.hpp` remains a compiler workaround until its ordering
constraint disappears or it can be generated safely.

This is a whole-module migration.  Converting aliases and forward declarations
inside a legacy file that is about to be deleted is not progress.

## Execution status

The first generated graph slice is complete and gated. `errors` and
`circuit_breaker` now come from valid Rust owners, with a shared generated
`monotonic` support module. Their two legacy module files are deleted. Gate 131
built cleanly, enumerated all 179 tests, retained `rpcbench` as the only failure,
and preserved the prior 124-entry Not-Run set. The current census is **1,181
scaffold lines** plus the unchanged **35-line C ABI floor**.

The next executable slice is deliberately feature-led: transparent nullable
callback lowering unlocks `connection_state` and `heartbeat`; exact trait-object
and inheritance lowering unlocks `pollable_proxy` and the channel leaves. The
generator's consumer-module map is being hardened against nested modules,
aliased/glob imports, and fully qualified paths before those graph layers are
added.

The 35 remaining named-module interfaces account for exactly **1,022** of the
1,202 scaffold lines.  Retiring all of them leaves a precisely identified
180-line non-interface envelope: `std_compat.hpp` (93), `rrr.hpp` (30), the
fiber C header's scaffold portion (23), import shims (18), the selected epoll
implementation unit (10), and `base/all.hpp` (6).  The first realistic
majority milestone is the 29 interfaces without a hard C++ semantic boundary:
555 lines removed, reducing total scaffold to 647.

## Non-negotiable invariants

1. Every owner under `crates/srpc` is valid, warning-free Rust.  Inline-Rust
   DSL fragments are specifications and porting aids, not files to copy
   verbatim.
2. The checked-in C++ is deterministic output of the pinned rusty-cpp emitter.
   Configure-time stamp validation remains offline and fail-closed.
3. A module is retired only after its exported names, signatures, enum values,
   layout/traits where relevant, and runtime behavior have been compared with
   the legacy module.
4. Wire bytes, RPC error values, callback sequencing, exception behavior,
   source-location capture, and the fiber ABI are contracts.
5. Each graph batch passes Rust tests, generator drift checks, focused C++
   import/runtime probes, the Mako build, and the 179-test gate.  A batch is
   committed and pushed before the next risky graph layer starts.
6. Generated compatibility headers may remain compiler inputs, but they are
   never treated as authored C++.

## Generator architecture

`crates/srpc/cpp/mako-consumer.toml` becomes the only project-side description
of the C++ consumer.  Each unit records:

- Rust owner module and source;
- legacy C++ module name;
- C++ namespace (flat `rrr` for this consumer);
- direct Rust-module dependencies;
- interface or implementation-unit role;
- global-module-fragment headers and compatibility shims;
- API/layout probe metadata once that planned schema extension lands (for now,
  probes remain explicit C++ tests beside the consumer).

The implementation is split into four enabling increments:

1. **Consumer module map.** Map a Rust module path to the consumer's C++ module
   and namespace.  It must control emitted imports and qualified type and
   expression paths; injecting textual imports after generation is
   insufficient.
2. **Graph generation.** Validate dependencies topologically and against the
   emitted imports, derive the CMake module source list, and reject unexpected
   or privately exported output. Schema v3 intentionally permits one unit per
   module; a later unit-ID extension must land before the epoll interface can
   own one interface plus implementation units.
3. **C++ surface metadata.** Add rustc-hidden mappings only where a valid-Rust
   compatibility facade would otherwise distort the crate: C++ names,
   declaration-only items, default arguments, `noinline`, `c_char`, and exact
   foreign/STL carrier types. A transparent
   `Option<Box<dyn Fn/FnMut>> -> rusty::Function` mapping is also required:
   Rust's `Option` and the C++ function wrapper represent the same nullable
   callback contract, while emitting `Option<Function>` changes layout.
4. **Generated envelopes.** Emit import shims, `rrr.hpp`, and `base/all.hpp`
   from the manifest.  A later, separate C-header backend may own
   `srpc_fiber.h`; the C++ module emitter must not pretend that C can consume a
   generated C++ class layout.

## Dependency-ordered migration

The line targets below use the post-pilot census.  They are planning weights,
not a substitute for the exact per-commit census.

| Batch | Modules | Scaffold target | Primary prerequisite |
|---|---|---:|---|
| 1. Independent reliability leaves | `errors`, `connection_state`, `circuit_breaker`, `heartbeat`, `load_balancer`, `pollable_proxy`, `callback_wrapper`, `request_options`, `reconnect_policy` | 96 | consumer module map; exact legacy API facades |
| 2. Base/runtime prerequisites | `basetypes`, `misc`, `rand`, `threading`, `debugging`, `logging`, `cpuinfo`, `utils`, `epoll_wrapper` + Linux implementation | 211 | extern-C and C-char mappings; default/attribute metadata; interface/implementation units |
| 3. Wire, serialization, and queues | `frame_codec`, `idempotency`, `completion_tracker`, `request_queue`, `serializable`, `serializable_envelope`, `any_message` | 201 | shared declaration collection; ADL/declaration-only support; exact container carriers |
| 4. Channel transports | `callbacks`, `channel`, `inmemory_channel`, `fiber_channel`, `tcp_channel` | 158 | batches 1--3; callback and platform surfaces |
| 5. Reactor | `future`, `fiber`, `reactor` | 228 | batches 2 and 4; multi-unit ordering and runtime ABI probes |
| 6. Endpoints | `client`, `server` | 138 | all lower layers |
| 7. Generated envelopes | `rrr.hpp`, `base/all.hpp`, import-only `*.hpp` shims, and eventually `std_compat.hpp` | 147 | manifest owns the complete graph |

`srpc_fiber.h` accounts for the remaining 23 scaffold and 35 logic census
lines.  It stays explicit until a Rust `repr(C)` to C11 header backend proves
both x86-64 and AArch64 sizes, alignments, offsets, nullable raw callback
layout, and assembly constants.

Six interfaces are treated as explicit split/defer boundaries rather than
being forced through an unsafe approximation: `debugging` (caller-capturing
`source_location`), `serializable` (variadics, ADL and overload-set lookup),
`any_message` (checked RTTI), `reactor` (fiber ABI and raw handles), `client`
(variadic/lifetime bridges), and `server` (structural service checks and
type-erasure).  Rust can own the rest of each module while a narrow companion
kernel remains, but the replacement must preserve those contracts exactly.

## Per-module retirement protocol

1. Port or reshape the behavior into its final Rust owner; keep native Rust
   tests outside generated production files when test-only modules would emit
   hand slots.
2. Add the unit and dependency edges to the consumer manifest and regenerate.
3. Compile both old and generated modules in isolation and run a shared C++
   API probe.  Compare exported symbols when that is meaningful.
4. Switch CMake to the generated unit, remove the legacy source from all globs
   and borrow-check inputs, delete the legacy file, and reconfigure so stale
   glob entries cannot survive.
5. Run focused legacy tests, generator `--check`, the full build/gate, census,
   commit, and push.

## Residual policy

When a module cannot migrate, record the exact missing Rust or emitter feature
at the graph edge that requires it.  Do not preserve an entire legacy file for
a two-line kernel: move a C ABI kernel to an existing C translation unit, or
teach the generator to emit the necessary declaration while Rust owns the
surrounding module.  Conversely, do not weaken type safety, wire checks,
exception semantics, or fiber layout merely to reduce the census.
