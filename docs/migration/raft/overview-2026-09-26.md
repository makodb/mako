## 2. The shape of the code today

```
                 Mako / Paxos (C++)                        Raft
  ┌───────────────────────────────────┐   ┌─────────────────────────────────────┐
  │ raft_worker.cc, frame.cc,         │   │ class RaftServer (server.h:576)     │
  │ raft_main_helper.cc  (C++)        │──▶│   one member: RaftServerBase* impl_ │
  │                                   │   │   18 inline forwards                │
  │ RaftCommo (commo.cc)  ◀── sends ──┼───│                                     │
  │ RaftServiceImpl (service.cc) ─────┼──▶│ 31 C exports   (server_exports.h)   │
  │ C++ srpc::Server + poll thread    │   │         ▼                            │
  │   (libsrpc.a = reactor.rs         │   │ RaftServerBase  (server_h.rs:1774)   │
  │    transpiled to C++)             │   │ RaftConsensusState (server_h.rs:1033)│
  └───────────────────────────────────┘   │ heartbeat/AE/vote bodies (server_cc) │
                 ▲                         │         │ 91 raft_* kernels         │
                 └──── kernels (server.cc:452-1447, extern "C") ◀────┘          │
                                           │ transport.rs / service.rs / rpc.rs  │
                                           │   BUILT, TESTED, NOT WIRED IN (3e)  │
                                           └─────────────────────────────────────┘
```

- The Raft **server** is canonical Rust (`src/server_h.rs` 5,020 lines,
  `src/server_cc.rs` 2,774), built by cargo into `libraft.a` and linked with a
  RESCAN link group (`CMakeLists.txt:1274-1279`) because exports and kernels
  need each other.
- C++ knows `RaftServerBase` only as a forward-declared name (`server.h:561`).
  `python3 scripts/raft_field_census.py` = 0 hand-written field accesses.
- The **RPC path is still C++**: `RaftCommo` sends, `RaftServiceImpl`
  dispatches (now a null check + one `Serve*` call per RPC), both on the C++
  srpc poll thread `svr_poll_thread_worker_` (`raft_worker.cc:344`).
- The Rust RPC lane (`src/transport.rs`, `src/service.rs`, generated
  `src/rpc.rs`) exists and is inert: `transport_of()` returns None because
  nothing calls `raft_transport_serve`, and `transport_exports.h` is included
  by nothing.

### Control flows (Rust entry → C++ kernels)

- **Startup**: `EnsureSetup` (`server_h.rs:4653`) → `Setup` → `raft_setup_internal_guarded`
  (C++, `raft_catch`) → back into `SetupInternal` (`:2610`) →
  `raft_bind_replication_poll` (`:2635`, gets the C++ PollThread from commo) →
  snapshot recovery → `raft_spawn_apply_thread` (std::thread) →
  `raft_spawn_heartbeat_loop` + `raft_spawn_election_timer_fiber` (C++ fibers).
- **Election**: timer fiber → `ElectionTimerLoop::run` → `RequestVoteImpl` (`:4042`) →
  `raft_broadcast_vote_and_wait` (call `:4149`; C++ `server.cc:489` does
  `BroadcastVote` + `wait_timeout(1s)` on a C++ quorum event) →
  `raft_vote_quorum_snapshot` → `setIsLeader`.
- **Heartbeat**: `HeartbeatDriver::run` (`server_cc.rs:1838`): phase 0 commit/authority,
  phase 1 payload selection + sends (`raft_phase1_send_append` `:1226`,
  `raft_phase1_load_and_send_snapshot` `:1164`), phase 2 replies
  (`raft_append_response_read`), phase 3 commit advance + enqueue. Waits via
  `raft_int_event_wait_timeout` (`server.cc:1470`).
- **Wake**: `RequestReplication` → `raft_queue_wake_job` → C++ PollThread job →
  `raft_wake_job_run` export → `GateWakeJob::run` → `raft_int_event_set`.
- **Inbound**: `ServeVote`/`ServeAppendEntries`/`ServeInstallSnapshot`
  (`server_h.rs:4819/4833/4855`) — gate applied in Rust, bodies in `server_cc.rs`.
  AppendEntries payload decoding still goes through C++ kernels
  (`raft_wire_is_batch`, `raft_batch_*`, `raft_wire_command_clone_into`).
- **Apply**: std::thread `ApplyThreadLoop` (`:3451`) → `raft_apply_invoke`
  (C++ callback, `raft_catch`); snapshots via `raft_snapshot_serialize_and_save`.
- **Submit**: `Start` (`:4778`) → `raft_command_clone_into` → `AppendLocal` → `RequestReplication`.

### The boundary, counted

- **31 exports** C++→Rust (`server_exports.h`, defined `server_cc.rs:2496-2770`):
  2 lifetime, 2 fiber-loop bodies, 1 wake job, 18 interface (3 are `TxLogServer`,
  shared with Paxos: `set_commo`, `set_site_identity`, `reg_learner_action`;
  15 `RaftSpecific`), 8 kernel callbacks.
- **91 kernels** Rust→C++ under the generator's rule (73 server + 2 service +
  16 lab). By purpose: locks 4, reactor/fiber 9, threads 3,

  snapshot 10, logging/verify 2, guards 1.
- Irreducible while Mako owns them: `janus::Command` handling, `dynamic_cast`
  in `raft_bind_commo`, the 7 `raft_catch` sites, the embedder `std::function`s,
  `SnapshotManager` virtuals. Everything reactor/fiber/thread/time is C++ only
  because of where the boundary sits.

## 4. Open item 1 — the latency regression (verified)

**Cause confirmed.** `src/srpc/reactor/reactor.rs:1534-1536` and `:1553-1555`
retain events with `status() != EventStatus::DONE` only. At `bbbd51d89` both read
`status != DONE && status != TIMEOUT`, with a comment explaining the leak.
`move_matching` pulls out only READY events, so every TIMEOUT event stays in
`waiting_events_`/`composite_events_` forever and is rescanned every pass.
Raft does one timed wait per heartbeat round per replica.

Additional facts the docs do not state:

- **Only that clause was lost.** The rest of Mako-local `7f52613fe` (BoxEvent
  Mutex+AtomicBool, admission gate, future.rs) survived. The squash message's
  "Upstream's own TIMEOUT-eviction fix was kept" is misleading — upstream only
  has a quorum-specific drain guard (srpc `7b3df6aab`).
- **An existing test should already be failing**: `src/srpc/tests/test_timeout_race.cc`
  `TimeoutEventCleanup` (`:158-241`) asserts no TIMEOUT event remains in either
  queue. It is ctest target `test_srpc_timeout_race` (`CMakeLists.txt:1903-1913`).
  Worth running first — it is the cheapest proof, before and after the fix.
- **Both lanes get the fix.** The C++ libsrpc reactor is this file transpiled
  (`src/srpc-cmake/CMakeLists.txt:547-557` → `build*/src/srpc/goal0-crate-cpp/srpc.reactor.cppm`).
  Nothing generated is checked in; a rebuild regenerates it. Paxos, Mako and
  C++ Raft all run on it.
- **Safe**: nothing relies on TIMEOUT events staying queued; fibers inspect
  status on their own Arc, and `event_test_impl` treats TIMEOUT as a no-op.
- **mako-dev has the same leak** (`/home/users/zyang2/mako/src/srpc/reactor/reactor.rs:1524`, `:1543`),
  but there it is upstream's latent bug, not a regression — mako-dev never had
  `7f52613fe`. It also lacks the BoxEvent fix and the extended test. The
  eviction fix belongs there and upstream too.

## 5. Open item 2 — stage 3e cutover (NOT ready to flip)

The plan's site list mostly still matches (only `server_h.rs:4141` drifted;
the vote call is now `:4149`). But reading the code turned up gaps the plan
does not record. Each can land inert (behind `transport_of() == None`) before
the switch:

1. **Wire bug in generated AppendEntries** — confirmed by this session.
   `src/rpc.rs:97` serializes `cmd: Vec<u8>` with a v64 length prefix
   (`src/srpc/misc/serializable.rs:529-537`); `from_body` (`rpc.rs:135-162`) and
   the generator (`scripts/rpcgen_rust.py:75-93`) treat `cmd` as unframed bytes
   from offset 50. A Rust-sent AppendEntries with a command would misdecode on
   both lanes. Fix in `rpcgen_rust.py` (write the bytes raw) + a golden test.
2. **No Command→bytes kernel** for the send side (only `raft_command_from_bytes`,
   `raft_byte_string_from_bytes` exist, `server.cc:553`, `:570`).
3. **ABI mismatch**: `raft_command_from_bytes` returns `bool` in C++
   (`server.cc:553`) but is declared `-> ()` in `service.rs:35`, so a malformed
   frame is served as an empty Command instead of rejected.
4. **No EmptyAppendEntries send path** in `transport.rs`, although C++ picks it
   when there is no command (`commo.cc:69`) and `RaftProxy::empty_append_entries_async` exists.
5. **Transport ABI is missing** set-admission-ready, bound-port and
   post-job-to-poll-thread; `serve()` leaves admission OPEN at start whereas C++
   closes it before start (`raft_worker.cc:351`).
6. **`add_peer` connects once, no retry**; C++ `ConnectToAddress` retries for
   `CONNECT_TIMEOUT_MS`, and `ReconnectToSite` has no Rust counterpart.
7. **More fiber-coupled kernels than the plan's three**: also
   `raft_spawn_election_timer(_fiber)`, `raft_fiber_sleep_us`, the IntEvent
   kernels (`server.cc:1460-1478`), `raft_queue_wake_job`, plus the
   `EnsureSetup` jobs (`raft_main_helper.cc:471`, `:540`) and **the lab-test
   fiber in `frame.cc:279-354`**, which must move too or RaftLabTest runs on
   the wrong reactor.
8. **InstallSnapshot completes by callback** (`server.cc:1654-1700`); `Pending<T>`
   has no poller — needs a callback-shaped send or a poll site, keeping the
   "no-peer path passes 0 without a lock" rule.
9. **Vote semantics differ slightly** from C++: Rust decides a loss after
   `n - majority` rejections (C++ effectively waits out the timeout in a
   3-node group), counts self in `n_voted_yes_`, and seeds max term with the
   candidate's term. Probably fine, must be a conscious choice.
10. **Shutdown order**: drain → quiesce → drop server → drop scheduler → stop
    poll thread. Rust `PollThread` stops on drop; must not drop early.
11. **kSingleGroup stubs** (`raft_main_helper.cc:370-394`) need one server per
    site; `serve()` binds one per transport — either one transport per stub or
    a serve-only variant.

Done criterion (plan): RaftLabTest 25/25 served entirely by the Rust lane AND a
before/after RPC benchmark with no regression.
