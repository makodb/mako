--------------------------------------------------------------------------------
 0. HOW ONE SOURCE SERVES TWO CONSUMERS
--------------------------------------------------------------------------------

 Every block is read by TWO different tools that must not see the same
 directives:

   * rustc     -- the gate extracts the Rust and compiles it with
                  `rustc --edition=2021 --crate-type=lib -D warnings`
                  (scripts/raft_dsl.sh:329-331). This proves the block is real
                  Rust, not C++ wearing Rust syntax.
   * rusty-cpp -- the pinned transpiler renders the block into the adjacent
                  GEN block, which is what the C++ compiler actually sees.

 The split is done with two always-constant cfg predicates:

   #[cfg_attr(any(), X)]        any() is ALWAYS FALSE
                                -> rustc ignores X entirely
                                -> the transpiler still reads X
                                => "X is a directive FOR THE TRANSPILER"

   #[cfg_attr(not(any()), X)]   not(any()) is ALWAYS TRUE
                                -> rustc applies X
                                -> the transpiler ignores X
                                => "X is a directive FOR RUSTC"

 So in a wire record you will see both on the same struct:

   #[cfg_attr(any(), cpp_no_auto_traits)]                        <- transpiler
   #[cfg_attr(not(any()), derive(Clone, Copy, Debug, Default,    <- rustc
                                 Eq, PartialEq))]
   #[repr(C)]                                                    <- BOTH

 `repr(C)` carries no cfg_attr because both consumers need it: rustc for
 layout, the transpiler to know it may emit a plain aggregate.

 THE OTHER LEVER: `const fn` vs `fn`.
 quorum.hpp:45-47 states it outright in a comment --
   "`const fn` makes the generated C++ constexpr (and thus implicitly inline)
    without a textual post-processing pass."
 So `pub const fn` -> `constexpr` (implicitly inline, usable in
 static_assert); plain `fn` -> an ordinary out-of-line function. This is the
 author's only handle on inlining, and it is chosen per function.

 1. THE MINIMUM CASE -- snapshot_manager.hpp:42-56
--------------------------------------------------------------------------------

 RUST:
   pub const fn snapshot_metadata_is_valid(last_included_index: u64) -> bool {
       last_included_index > 0
   }

 GENERATED C++:
   constexpr bool snapshot_metadata_is_valid(uint64_t last_included_index);
   constexpr bool snapshot_metadata_is_valid(uint64_t last_included_index) {
       return rusty::detail::deref_if_pointer_like(last_included_index) > 0;
   }

 ADJACENT, AUTHOR-WRITTEN (not generated):
   static_assert(!snapshot_metadata_is_valid(0));
   static_assert(snapshot_metadata_is_valid(1));
   static_assert(snapshot_metadata_is_valid(UINT64_MAX));

 WHAT TO NOTICE
  * A forward declaration is always emitted, then the definition.
  * `u64` -> `uint64_t`. Rust's fixed-width integers map 1:1, which is why
    scalar code converts cleanly and `size_t`/`ballot_t`-style
    preprocessor-selected aliases do not (see section 10).
  * `deref_if_pointer_like(x)` wraps EVERY operand. For a scalar it is the
    identity; it exists so the same emitter path works when the operand is a
    smart pointer. It is noise here, not cost.
  * The static_asserts are hand-written next to the block, never inside it.
    Zero of the 534 static_asserts in the 21 carriers sit inside a GEN region.
    They pin what the AUTHOR TRANSCRIBED as the old behaviour; nothing
    mechanically links them to the deleted C++.

 RUST:
   pub const fn raft_quorum_reached(received: i32, needed: i32) -> bool {
       received >= needed
   }
   pub const fn raft_quorum_majority_count(total: usize) -> usize {
       (total / 2) + 1
   }
   pub const fn raft_quorum_count_reached(count: usize, quorum: usize) -> bool {
       count >= quorum
   }
   pub const fn raft_quorum_count_below(count: usize, quorum: usize) -> bool {
       count < quorum
   }

 GENERATED C++ (all four forward-declared first, then defined):
   constexpr size_t raft_quorum_majority_count(size_t total) {
       return ((rusty::detail::deref_if_pointer_like(total)
                / static_cast<size_t>(2))) + static_cast<size_t>(1);
   }

 WHAT TO NOTICE
  * `usize` -> `size_t`. Integer literals are explicitly cast to the operand
    type rather than left as untyped literals -- the emitter never relies on
    C++ integer promotion.
  * Redundant parentheses are preserved from the Rust expression tree. The
    output is a faithful lowering of the AST, not reformatted C++.
  * This is the shape 225 of the raft DSL functions have: free function,
    scalar in, scalar out, single expression. It is why the conversion has
    gone as far as it has, and why it stops where it does.

 3. AN ENUM -- recovery_manager.hpp:38-62
--------------------------------------------------------------------------------

 RUST:
   #[allow(non_camel_case_types)]
   #[cfg_attr(not(any()), derive(Clone, Copy, Debug, Eq, PartialEq))]
   #[repr(i32)]
   pub enum RecoveryMode {
       FRESH_START = 0,
       NORMAL_RECOVERY = 1,
       FORCED_FRESH = 2,
   }

 GENERATED C++:
   enum class RecoveryMode : int32_t;
   constexpr RecoveryMode RecoveryMode_FRESH_START();
   constexpr RecoveryMode RecoveryMode_NORMAL_RECOVERY();
   constexpr RecoveryMode RecoveryMode_FORCED_FRESH();

   enum class RecoveryMode : int32_t {
       FRESH_START = 0, NORMAL_RECOVERY = 1, FORCED_FRESH = 2
   };
   inline constexpr RecoveryMode RecoveryMode_FRESH_START()
       { return RecoveryMode::FRESH_START; }
   ... one per variant ...

 WHAT TO NOTICE
  * `#[repr(i32)]` fixes the C++ underlying type. The incumbent's discriminant
    values are preserved literally, which is what makes an enum swap safe.
  * Each variant ALSO gets a `constexpr` accessor function. That is the
    "lower self-referential associated consts as lazy accessors" behaviour
    from the pinned emitter's lineage (commit 91f617d4). Harmless, and it lets
    a variant be named from a context where the enumerator itself is awkward.
  * `#[allow(non_camel_case_types)]` is needed because the incumbent's
    SCREAMING_CASE variant names violate Rust naming -- and the gate compiles
    with `-D warnings`, so an un-silenced lint is a hard failure. Preserving
    the C++ spelling costs one allow attribute.

 4. A SECOND ENUM, DIFFERENT WIDTH -- replicated_db.h:28-52
--------------------------------------------------------------------------------

 RUST:
   #[repr(u8)]
   pub enum ReplicatedDBOp { PUT = 1, DELETE = 2, BATCH = 3 }

 GENERATED C++:
   enum class ReplicatedDBOp : uint8_t { PUT = 1, DELETE = 2, BATCH = 3 };
   (plus the three constexpr accessors)

 WHAT TO NOTICE -- AND THE TRAP
  docs/migration/rustycpp/raft-rust-migration.md records that Stage 1 owns this
  declaration only because the EMITTED C++ still accepts every raw `u8`,
  including values not named by any variant, with the same switch behaviour as
  before. It is explicitly NOT ready for native Rust: a real Rust enum cannot
  hold an unnamed discriminant, and `KVOperation` is transiently
  value-created with zero -- which is not PUT, DELETE or BATCH.

  This is the clearest example of a substitution that is safe as generated C++
  and unsafe as actual Rust. The DSL stage hides the difference; Stage 2
  (a real Rust crate) would expose it. Fixing it needs a transparent byte
  newtype or validated decoding, not another mechanical move.

 5. A WIRE RECORD, AND WHY THE TRANSPILER PIN IS ON AN UNMERGED BRANCH
--------------------------------------------------------------------------------
 messages.hpp:138-162

 RUST:
   #[cfg_attr(any(), cpp_no_auto_traits)]
   #[cfg_attr(not(any()), derive(Clone, Copy, Debug, Default, Eq, PartialEq))]
   #[repr(C)]
   pub struct AppendEntriesReply {
       #[cfg_attr(any(), cpp_value_init)]
       pub follower_append_ok: u64,
       #[cfg_attr(any(), cpp_value_init)]
       pub follower_current_term: u64,
       #[cfg_attr(any(), cpp_value_init)]
       pub follower_last_log_index: u64,
       #[cfg_attr(any(), cpp_value_init)]
       pub follower_ack_type: u64,
   }

 GENERATED C++:
   struct AppendEntriesReply;
   struct AppendEntriesReply {
       uint64_t follower_append_ok{};
       uint64_t follower_current_term{};
       uint64_t follower_last_log_index{};
       uint64_t follower_ack_type{};
   };

 WHAT TO NOTICE -- THIS ONE MATTERS BEYOND ITSELF
  * `cpp_value_init` exists to emit the `{}` default member initializer. The
    incumbent C++ had `uint64_t x{};` on every field. Without the marker the
    emitter produces a bare `uint64_t x;`, and default construction silently
    stops zeroing -- a behaviour change, not a cosmetic one.
  * That marker is the ONLY capability the pinned emitter
    (77c3ad5a, "transpiler: support scalar value-init marker") has that a
    main-reachable emitter does not. It lives solely on the unmerged branch
    origin/codex/raft-value-init == refs/pull/48/head.
  * `cpp_value_init` appears in exactly ONE file repo-wide: messages.hpp,
    38 field markers. So the entire reason this project cannot sit on
    rusty-cpp `main` is this one file's default initializers.
  * The marker is deliberately restricted to named ordinary-struct fields
    whose type is exactly a built-in bool or integer. It rejects float,
    char, pointer, reference, array, alias and container uses. Extending it
    would need a separate ABI contract and an emitter change.
  * `cpp_no_auto_traits` suppresses the emitter's automatic trait emission so
    the record stays a plain copyable aggregate. `derive(...)` on the other
    line is for rustc only. Same struct, two audiences, section 0.

 6. THE ONLY LOOP, AND THE ONLY RAW POINTERS -- snapshot_format.hpp:330-366
--------------------------------------------------------------------------------

 RUST:
   pub const unsafe fn snapshot_crc32_update_buffer(crc: *mut u32,
                                                    data: *const u8,
                                                    size: usize,
                                                    table: *const u32) {
       let mut i: usize = 0;
       while i < size {
           let byte = unsafe { *data.add(i) };
           let table_index = snapshot_crc32_table_index(unsafe { *crc }, byte);
           let table_value = unsafe { *table.add(table_index) };
           let next_crc =
               snapshot_crc32_update_from_table(unsafe { *crc }, table_value);
           unsafe { *crc = next_crc };
           i += 1;
       }
   }

 GENERATED C++:
   constexpr void snapshot_crc32_update_buffer(uint32_t* crc,
                                               const uint8_t* data,
                                               size_t size,
                                               const uint32_t* table);
   // @unsafe
   constexpr void snapshot_crc32_update_buffer(...) {
       size_t i = static_cast<size_t>(0);
       while (rusty::detail::deref_if_pointer_like(i)
              < rusty::detail::deref_if_pointer_like(size)) {
           const auto byte = *rusty::ptr::add(data, std::move(i));
           const auto table_index = snapshot_crc32_table_index(*crc,
                                                        std::move(byte));
           const auto table_value = *rusty::ptr::add(table,
                                                     std::move(table_index));
           auto next_crc = snapshot_crc32_update_from_table(*crc,
                                                    std::move(table_value));
           // @unsafe
           {
               *crc = std::move(next_crc);
           }
           i += 1;
       }
   }

 WHAT TO NOTICE
  * `*mut u32` as an OUT-POINTER lowers cleanly to `uint32_t*`. This refutes a
    claim that circulated in earlier status notes: out-parameters are NOT
    outside the DSL's reach. What blocks OnAppendEntries is not the
    out-pointers themselves (see section 9).
  * `data.add(i)` -> `rusty::ptr::add(data, i)`; `unsafe { *p }` -> `*p` with
    an `// @unsafe` annotation carried into the output.
  * `std::move(i)` on a `size_t`. Rust move semantics are lowered literally
    even for trivially-copyable types. It is a no-op for codegen but it is
    the clearest sign the output is a mechanical lowering, not idiomatic C++.
  * The `unsafe fn` is still `const` -> `constexpr`, so the hot kernel stays
    inline-able.
  * WHY RAW POINTERS AT ALL: the header comment says it preserves the
    incumbent's legal `unsigned char` view when the input aliases the CRC32
    object's own representation. A safe `&[u8]` would have changed the
    aliasing contract. This is a case where the DSL deliberately declines to
    be safer than the code it replaces.
  * The migration doc claims this kernel is "instruction-for-instruction
    identical to the incumbent". There is NO artifact behind that claim: no
    checked-in disassembly, no objdump script, no CI step. Repo-wide the only
    `objdump|disassembl|perf stat` hit is docs/masstree-test-plan.md:337,
    about Masstree, and it is a plan.
  * This block DOES have the project's only differential oracle:
    tests/raft_memory_snapshot_manager_test.cc:67 keeps the exact
    pre-migration loop as `IncumbentCRC32Update`, table-parameterized, and
    asserts equal output at :176 and :192. It compares VALUES, not time.

 7. CROSSING THE FFI BOUNDARY -- raft_main_helper.cc:152-196
--------------------------------------------------------------------------------

 RUST:
   fn equals_ignore_case(lhs: &str, rhs: &str) -> bool {
       if lhs.len() != rhs.len() { return false; }
       let lhs_bytes = lhs.as_bytes();
       let rhs_bytes = rhs.as_bytes();
       let mut i: usize = 0;
       while i < lhs_bytes.len() {
           if unsafe { tolower(lhs_bytes[i] as i32) } !=
               unsafe { tolower(rhs_bytes[i] as i32) } { return false; }
           i += 1;
       }
       true
   }
   unsafe extern "C" { fn tolower(value: i32) -> i32; }

 GENERATED C++:
   bool equals_ignore_case(std::string_view lhs, std::string_view rhs);
   extern "C" { int32_t tolower(int32_t value); }
   bool equals_ignore_case(std::string_view lhs, std::string_view rhs) {
       if (rusty::len(lhs) != rusty::len(rhs)) { return false; }
       const auto lhs_bytes = rusty::as_bytes(lhs);
       const auto rhs_bytes = rusty::as_bytes(rhs);
       size_t i = static_cast<size_t>(0);
       while (rusty::detail::deref_if_pointer_like(i)
              < rusty::len(lhs_bytes)) {
           if (tolower(static_cast<int32_t>(lhs_bytes[i]))
               != tolower(static_cast<int32_t>(rhs_bytes[i]))) return false;
           i += 1;
       }
       return true;
   }

 WHAT TO NOTICE
  * `&str` -> `std::string_view`. This is the ONE string type that crosses
    cleanly, because it is a non-owning view with no allocation contract.
    Owning `String` would render as a different, move-only C++ type -- which
    is exactly why the command- and string-bearing records stayed C++.
  * `.len()` -> `rusty::len()`, `.as_bytes()` -> `rusty::as_bytes()`.
  * `unsafe extern "C"` is how a libc function is reached. The declaration is
    re-emitted as a C++ `extern "C"` block. This is the sanctioned bridge
    shape: narrow, declared in the block, annotated unsafe.
  * NOTE the plain `fn`, not `const fn` -- so the generated function is NOT
    constexpr and NOT implicitly inline. Contrast section 2.
  * The semantics are deliberately legacy-faithful: `tolower` is
    locale-sensitive and this operates on raw argv bytes, so bytes above
    ASCII fold per the process locale. Canonical Rust would have to use an
    OS-string or byte-slice boundary rather than build a `&str` from
    unvalidated argv. Another safe-as-C++, unsound-as-Rust case.

    boolean algebra; the hand-written C++ kept the field reads, the lock, and
    the branch that acts on the answer.
  * So the pattern across the whole state machine is: EXTRACT THE PREDICATE,
    LEAVE THE STATE. server.cc calls these 163 times. The decision logic has
    genuinely moved; the machine around it has not.

 9. THE SPLIT MADE EXPLICIT -- snapshot_format.hpp:370-400
--------------------------------------------------------------------------------

 Immediately after the CRC32 GEN block of section 6, still hand-written C++:

   class CRC32 {
    public:
     // @safe - Default constructor
     CRC32() : crc_(snapshot_crc32_initial()) {}

     // @unsafe - Reads from raw pointer
     void Update(const char* data, size_t size) {
       snapshot_crc32_update_buffer(
           &crc_, reinterpret_cast<const uint8_t*>(data), size, TABLE);
     }

     // @safe - Returns final CRC value
     uint32_t Finalize() const { return snapshot_crc32_finalize(crc_); }

    private:
     uint32_t crc_;
     ...
   };

 WHAT TO NOTICE -- THIS IS THE ANSWER TO "WHY IS THE MIGRATION STUCK"
  * The DSL owns the COMPUTATION. Hand C++ owns the OBJECT.
  * `crc_` is one `uint32_t` of state. Even that stays in C++, because the
    DSL has no way to own a class with a mutable member and methods that
    mutate it. `Update` exists only to take the address of the member and
    hand it to the DSL function.
  * CLAUDE.md names this split as the intended design -- "DSL owns the shape,
    C++ owns the surgery" -- but here it inverts: the DSL owns a leaf
    computation while C++ owns the shape. That inversion is the migration's
    real ceiling.
  * The migration doc states the mechanism: "an `impl` for a hand-written C++
    class emits an orphan placeholder", so existing class methods cannot be
    projected independently. Hence 39 blocks with ZERO impls, ZERO traits,
    ZERO methods and ZERO containers in the raft DSL.

 10. WHAT THE GATE FORCES, AND WHY IT CAPS THE ABOVE
--------------------------------------------------------------------------------

 scripts/raft_dsl.sh:329-331 compiles each carrier's extracted payload with:

   rustc --edition=2021 --crate-name raft_dsl_carrier_N \
         --crate-type=lib -D warnings <payload> -o <rlib>

 No `--extern`. No `-L`. So EVERY CARRIER MUST BE A SELF-CONTAINED,
 DEPENDENCY-FREE RUST LIBRARY. Consequences:

  * No repo crate can be referenced -- so no `rusty::Vec`, `rusty::Arc`,
    `rusty::Mutex`, and no type defined in another carrier.
  * `-D warnings` means every unused item or naming deviation is a hard
    failure, which is why the blocks are peppered with `#[allow(dead_code)]`
    and `#[allow(non_camel_case_types)]`.
  * The stateful DSL idiom used elsewhere in this repository
    (src/cluster/*.h has 15 impls and 1 trait; src/deptran/mako_commands.h has
    19 impls) CANNOT pass this gate -- those carriers are regenerated by a
    different, unpinned script with no rustc stage.

 So the raft lane is: free functions, POD structs, C-like enums, std-only
 Rust, one carrier at a time. Sections 1-8 are what fits. Section 9 is what
 does not. The way out is NOT to relax this gate -- it is the only stage that
 proves the Rust is real -- but to stand up Stage 2, a raft Cargo crate with a
 manifest, so `rusty` becomes a genuine `--extern` and carriers are checked as
 a module graph instead of 21 isolated files. src/rrr already runs exactly
 that with 37 manifest modules, 198 impls and 111 Mutex uses.
