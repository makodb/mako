# TSan suppressions for Masstree tests.
#
# Activate by exporting TSAN_OPTIONS before running a test binary:
#
#   export TSAN_OPTIONS="suppressions=$(realpath src/masstree/tsan_suppressions.txt):halt_on_error=1"
#
# The suppressions below scope out one reviewed class of report that is
# expected and not actionable in this codebase:
#
# 1. Intentional lock-free reads inside Masstree's optimistic
#    concurrency machinery. Masstree readers race against writers on
#    node fields (permuter, version, keylenx, etc.) by design — the
#    algorithm validates the read via a version-counter retry. TSan
#    correctly observes these races; they are not bugs.

# Masstree internal lock-free traversal / split / remove paths.
race:masstree_insert.hh
race:masstree_remove.hh
race:masstree_split.hh
race:masstree_struct.hh
race:masstree_scan.hh
race:masstree_tcursor.hh
race:masstree_get.hh
race:nodeversion.hh
race:kpermuter.hh

# Compiler intrinsics for fence / relax — surfaced incidentally.
race:masstree/compiler.hh

# The src/mako/spinlock.h entries that used to live here were
# removed once the spinlock was migrated to std::atomic<uint32_t>
# with explicit acquire/release ordering. See
# docs/masstree-sanitizer-findings.md, Finding 5 (fixed).
# STO's participant epochs and process-wide clocks are likewise fixed with
# lock-free atomics rather than suppressed. See Finding 9 in the same report.
# MassTrans version/lock words use layout-preserving atomic_ref operations
# rather than a suppression. See Finding 11.
# Masstree RCU participant publication/scanning and threadinfo one-time setup
# are atomic/once-ordered rather than suppressed. See Finding 12.
